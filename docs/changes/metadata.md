# 저장 뒤 상품 정보 수집 (3a)

소유자가 링크를 담으면 상품 이름과 가격이 저절로 채워지게 하는 단위다. 읽을 수 없는 페이지여도 저장한 링크는 남는다. 이전에는 저장한 링크가 모두 "정보 수집 대기"로 남았다. 수집 작업 행은 만들었지만 실행하는 코드가 없었다.

## 바뀐 동작

- `POST /api/links`는 바로 응답한다. 상품이 대기 중이면 Next `after()`가 응답 뒤에 수집을 실행한다. 소유자의 접근 토큰으로 만든, 토큰을 갱신하지 않는 별도 Supabase 클라이언트를 쓴다. `after()` 안에서는 쿠키를 쓸 수 없기 때문이다.
- 수집 상태는 DB RPC가 관리한다. 작업을 60초 임대로 가져가고, 같은 세대이고 임대가 맞을 때만 결과를 쓴다. 한 세대에 최대 3번 시도한다. 늦게 끝난 이전 세대의 결과는 상품을 바꾸지 않는다.
- 페이지는 `src/features/metadata/infrastructure/safe-fetch.ts`가 가져온다. 사설망·루프백·링크 로컬·클라우드 메타데이터·예약 주소와 IPv4 매핑·NAT64 형태를 막는다. DNS 응답을 검증한 주소로만 연결하고 연결된 주소를 다시 확인한다. 리다이렉트는 최대 5번이며 매번 다시 검사한다. 15초, 압축 2 MiB, 해제 4 MiB 제한을 둔다.
- 이름은 JSON-LD Product, Open Graph, `<title>` 순서로 읽는다. 가격은 페이지에 서로 다른 가격이 하나만 있을 때만 저장한다. 같은 통화의 기존 값만 덮어쓴다. 이미지 주소는 3b를 위해 작업 행에만 남기고 API로 내보내지 않는다.
- 실패하면 원인 코드(14개 닫힌 목록)를 기록한다. 실패했거나 60초 넘게 멈춘 상품은 `POST /api/products/{productId}/metadata`로 다시 가져온다. 화면은 수집 중인 상품이 있으면 점점 길게 간격을 두고 다시 읽는다.
- HTML은 `htmlparser2` 12.0.0의 SAX 파서로 읽는다.

## 설계 선택

| 기준 | A. 소유자 세션 | B. 전용 작업자 |
| --- | --- | --- |
| 새 비밀 값 | 없음 | 작업자 토큰과 해시 테이블 |
| 권한 | 기존 소유자 확인과 RLS | 토큰으로 지키는 익명 실행 RPC와 새 역할 |
| 5단위 정기 작업 | 같은 내부 함수 위에 전용 역할과 래퍼 추가 | 같은 경로 재사용 |

A를 선택했다. B를 그린 후보도 3a만 보면 A가 낫다고 평가했다. 두 후보는 연결 주소 고정, 차단 표, 파서, 한 가격 규칙, 이미지 주소를 작업 행에 두는 방식에 동의했다. 같은 모델 계열의 두 후보이며 다른 계열 심사는 생략했다.

## 검증

| 검사 | 결과 |
| --- | --- |
| 단위 (`npm test`, 로컬 서버를 쓰는 가져오기 통합 포함) | 517개 통과 (이전 267개) |
| 실제 DB | persistence 59개, service 26개 통과 (이전 33·10개) |
| 실제 HTTP | 14개 통과. 루프백 주소 링크가 바로 201로 저장되고 `blocked_address`로 끝나며 링크가 남는다. |
| 실제 스택 브라우저 | 16개 통과 |
| 브라우저 e2e | 50개 통과 |

조정자가 구현 담당자와 별도로 `npm run verify`를 실행해 개수를 확인했다. 각 단계의 Red는 `docs/evidence/metadata/red-*.txt`에 있다. Service·HTTP·브라우저 검사는 동작을 만든 뒤 작성해 별도 Red가 없다.

실제 쇼핑몰 10곳의 결과는 [real-pages.md](../evidence/metadata/real-pages.md)에 있다. 29CM·오늘의집·11번가·IKEA·Apple은 이름과 가격, Amazon은 이름만 가져왔다. 쿠팡·SSG·올리브영은 자동 요청을 차단했고 무신사는 상품 정보를 찾지 못했다. 네이버 스마트스토어는 확인하지 못했다.

## 독립 검토와 수정

| 문제 | 수정 |
| --- | --- |
| 사용자 정보가 든 이미지 주소를 DB가 거절해 정상 이름·가격까지 잃고 재시도도 계속 실패했다. | DB 규칙에 맞지 않는 이미지 주소는 버리고 이름·가격은 저장한다. |
| 멈춘 작업을 재개하면 응답이 여전히 멈춤으로 표시돼 화면이 다시 읽기를 멈췄다. | 재개한 작업을 다시 대기열에 넣고, 멈춤 판정을 마지막으로 대기열에 들어간 시각 기준으로 바꿨다. |
| 매우 큰 세대 값이 400이 아니라 503이었다. | 요청 계약과 명령에서 정수 범위를 제한했다. |
| 브라우저 검사 하나가 DNS 동작에 의존했다. | 차단되는 IP 주소로 바꿨다. |

## 남은 범위

- 이미지 사본은 3b다. 자동 재시도와 정기 수집은 5단위다. 그 전까지 `after()`가 끝나지 못한 작업은 60초 뒤 멈춤으로 보이고 소유자가 다시 가져오기를 누른다.
- Vercel에서의 `after()`·`maxDuration` 동작, 실제 Google OAuth, 실제 iPhone은 검증하지 않았다.
- 실행 도중 접근 토큰이 만료되지 않는다는 가정은 supabase-js의 만료 90초 전 갱신에 기대며 따로 시험하지 않았다.
