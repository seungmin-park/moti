# 상품 사진의 비공개 사본 (3b)

소유자가 실제 보관함(`/`)에서 담아둔 상품마다 사진을 보게 하는 단위다. 사진은 Supabase Storage의 비공개 사본이며 쇼핑몰 주소를 직접 걸지 않고 공개하지도 않는다. 사진 복사가 실패해도 링크·이름·가격은 남는다. 이전에는 3a가 읽은 사진 주소를 작업 행에만 두었고 화면은 모든 상품에 "링크를 담아두었어요" 자리표시만 보였다.

## 바뀐 동작

- 같은 수집 실행 안에서 페이지를 읽은 뒤 사진을 복사한다. 작업은 이름·가격과 사진 결과를 한 번에 `metadata_complete`로 끝낸다. 임대·세대 검사는 그대로 SQL에만 있다.
- 사진 이름은 DB만 만든다. 작업을 맡으면 `<소유자>/<상품>/<작업>-<시도>.webp`를 돌려준다. 시도 번호가 이름에 들어가 임대가 끝난 이전 시도가 다음 시도의 사본을 건드릴 수 없다.
- 사진은 `safe-fetch.ts`의 같은 고정 연결 경로로 가져온다. 모듈 안의 한 가져오기 핵심을 페이지용과 사진용 두 출구가 쓴다. 사진 요청은 SVG가 아닌 `image/*`와 형식 미표시 바이너리만 받고 8 MiB, 10초 제한이며 상품 페이지의 출처만 Referer로 보낸다.
- 형식은 바이트로만 정한다(JPEG·PNG·GIF·WebP·AVIF). SVG·HTML·HEIC·TIFF·BMP·ICO는 사진으로 받지 않는다. sharp 0.35.5가 판별과 같은 형식인지 다시 확인하고, 25 MP 초과·잘린 파일을 거절하고, 회전 정보를 적용하고, 1200px 안으로 줄이고, 메타데이터 없는 WebP로 다시 만든다. 1 MiB를 넘으면 저장하지 않는다. 다시 만들기는 sharp의 5초 제한(`timeout`)을 두고 넘기면 `timeout`으로 기록한다. 로컬 Apple Silicon에서 25 MP PNG는 약 0.15초 걸렸다.
- 업로드는 소유자 접근 토큰으로 한다. 앱에 service role 키가 없다. 버킷 `product-pictures`는 비공개, 1 MiB, `image/webp`만 받는다. `storage.objects` 정책은 `moti_storage` 스키마의 함수(소유자 `moti_rpc`)를 부른다. 쓰기는 수집 중이고 임대가 살아 있는 작업의 예약된 이름에만, 읽기는 소유자 접두사에만, 삭제는 상품이 보여주지 않고 끝나지 않은 작업의 이번 시도 이름도 아닌 객체에만 허용한다. 완료는 임대가 지난 작업도 다시 맡기 전까지 받아들이므로 이번 시도의 사본은 임대와 상관없이 지우지 못한다. 덮어쓰기 정책이 없어 소유자 토큰의 직접 업로드는 같은 이름에 한 번만 성공한다. 서명 업로드 주소는 다르다. Storage는 주소를 발급할 때 쓰기 정책만 확인하고 업로드는 자기 역할로 쓴다. 그래서 임대 중에 발급한 주소로 2시간 동안 예약된 이름을 만들거나 덮어쓸 수 있다(로컬 Storage에서 확인). 완료는 저장된 객체의 `storage.objects.version`을 작업과 함께 `picture_object_version`에 기록한다. `picture_locate`는 버전이 같을 때만 이름을 돌려준다. 완료 뒤 바뀐 사본에는 새 서명 주소를 만들지 않고, 사진 경로는 404 `picture_missing`, 화면은 중립 자리표시를 보인다. 잃는 것은 사진뿐이다. API의 `picture_version`(작업 ID)과는 다른 값이며 응답에 나가지 않는다.
- 상품은 마지막으로 성공한 사본과 이번 세대의 사진 결과(`copied`·`absent`·`failed`와 원인)를 따로 둔다. 실패하거나 사진이 없어도 이전 사본은 남는다. 새 사본이 이전 사본을 대신하면 실행기가 이전 사본을 지운다. 세대가 바뀌어 결과가 반영되지 않으면 자기 사본을 지운다. 끝내기가 예외를 던지면 지우지 않는다. 시간 초과한 완료가 나중에 커밋돼 상품이 그 사본을 가리킬 수 있기 때문이다.
- 이름·가격은 가져왔지만 사진만 실패한 상품도 기존 "다시 가져오기"로 새 세대를 시작한다. 페이지도 다시 읽는다.
- 화면은 `GET /api/products/{productId}/picture?v=<작업>`을 이미지 주소로 쓴다. 이 경로가 접근을 확인하고 1시간짜리 서명 주소로 302 이동하며 이동 응답은 개인 캐시에 50분 둔다. 사본이 없으면 404 `picture_missing`이다. 보관함 JSON에는 이 같은 출처 주소와 사진 결과만 있고 객체 이름·서명 주소·쇼핑몰 사진 주소는 없다. 계약의 정규식이 이 형태를 강제한다.
- 카드와 상세는 `next/image`(`fill`, `unoptimized`, Referer 없음)로 사본을 보인다. 사본이 없으면 중립 회색 자리표시가 "사진을 가져오는 중", "사진을 가져오지 못했어요", "링크를 담아두었어요" 중 하나를 말한다. 이미지를 불러오지 못하면 "사진을 불러오지 못했어요"로 바뀐다. 상세는 사진 실패 이유와 "이름과 가격은 가져왔어요"를 보여준다. 다시 읽기 결과는 사진도 반영한다.
- 수집 실행은 단계마다 제한이 있다. 페이지 15초, 사진 10초, 정규화 5초이고 `after()`에서 쓰는 Supabase 호출(맡기·업로드·완료·지우기)은 각 10초다. Storage 업로드에는 중단 신호를 넘길 수 없어 호출 자체를 묶는다. 두 수집 경로의 `maxDuration`을 30초에서 60초로 늘렸다. 최악은 맡기 10 + 페이지 15 + 사진 10 + 정규화 5 + 업로드·완료·지우기 각 10 = 70초라 `maxDuration`을 넘을 수 있다. 그때 실행이 끊기면 작업은 임대(60초)가 지난 뒤 멈춤으로 보이고 소유자가 다시 가져오기를 누른다. 링크와 이미 저장한 이름·가격·사진은 잃지 않는다. 끊긴 실행이 올린 객체는 5단위 정리 대상이다.

## 설계 선택

| 기준 | A. 같은 수집 실행에서 복사 | B. 별도 사진 작업 |
| --- | --- | --- |
| 상태 | 상품 열 5개, 사진 작업 표 없음 | 표 1개, RPC 6개, 오류 코드 M0009 |
| 재시도 | 기존 재시도 RPC와 버튼, 페이지도 다시 읽음 | 사진만 다시 시도하는 새 경로 |
| 지연 | 이름·가격이 보통 0.5~2초 늦게 보임, 단계 제한의 합으로 최대 60초 | 이름·가격과 사진이 따로 보임 |
| 화면 상태 | 수집 상태 하나 | 수집과 사진 두 상태 |

상태와 재시도는 A를 택했다. 사진만 따로 다시 시도하는 이득이 두 번째 상태 기계·표·경로의 비용보다 작다. 화면 표시는 B의 같은 출처 경로를 택했다. A의 서명 주소 묶음은 만료 시각, 깨진 주소 집합, 모든 상품 응답의 서명을 화면 상태와 응답에 퍼뜨린다. B는 이것을 경로 하나에 모으고 계약에 nullable `src` 하나만 남긴다. 보이는 사진마다 함수 호출·인증 확인·서명이 한 번씩 더 드는 비용은 소유자 한 명의 보관함에서 받아들인다. 실제 첫 화면 측정이 다르게 나오면 다시 검토한다. 사본 이름의 소유자 접두사도 B에서 가져왔다. 테스트 정리와 이후 소유자 단위 정리가 접두사 목록 하나로 끝난다. 같은 모델 계열의 두 후보를 조정자가 합쳤고 다른 계열 심사는 생략했다.

## 남은 범위

- Vercel에서 `maxDuration` 60초, `after()` 시간, 함수에 sharp가 포함되는지와 25 MP 디코드 메모리는 검증하지 않았다. 배포는 별도 승인이다.
- 실제 Google OAuth와 실제 iPhone은 검증하지 않았다. 브라우저 검사는 로컬 Auth 세션과 iPhone 크기 WebKit이다.
- 서명 업로드 주소로 예약된 이름에 쓴 객체와 완료 뒤 바뀐 사본은 상품이 보여주지 않는 객체로 남는다. 5단위의 정리 작업이 지운다. Storage의 서명 주소에는 객체 이름만 있고 버전이 없다. 그래서 바뀌기 전에 서명한 주소는 만료될 때까지(서명 뒤 최대 1시간) 바뀐 바이트를 전달한다(로컬에서 확인). 업로드와 완료 사이(보통 수 밀리초, 최대 완료 제한 10초)에 바뀌면 완료가 바뀐 버전을 기록한다.
- 업로드 뒤 끝내기 전에 프로세스가 죽거나, 끝내기가 예외를 던지고 끝내 커밋되지 않거나, 지우기가 실패하면 상품이 가리키지 않는 사본이 남는다. 이름이 정해져 있어 5단위의 정리 작업이 10분보다 오래된 미참조 객체를 지울 수 있다. 상품 삭제(4단위)는 참조를 먼저 지우고 사본을 지워야 한다.
- 5단위의 매일 가격 확인이 이 실행기를 쓰면 같은 사진을 매번 다시 복사한다. 사진 주소가 같으면 건너뛰는 규칙은 만들지 않았다.
- 서명 주소는 하나씩 철회할 수 없다. 만료 직후 Smart CDN이 잠시 응답할 수 있다.
- 3b 이전에 완료된 상품은 사진 결과를 `absent`로 채웠다. 다시 가져오기는 이 상태를 받지 않으므로(`M0007`) 이 상품들은 사진 없이 남는다. 아직 배포한 적이 없어 실제 데이터에는 영향이 없다. 운영 데이터가 생긴 뒤에는 이 채우기를 다시 검토해야 한다.
