# 목업 이후 연결 계획

## 화면 피드백

먼저 이미지 중심 목록, 상세 정보, 링크 추가, 구매완료와 실행 취소, 컬렉션 관리, 수집 상태와 공유 저장 안내를 모바일과 PC에서 확인한다. 현재 데이터는 예시이고 새로고침하면 초기화된다.

## 실제 기능

화면 확정 후 Vercel 웹과 API, Supabase DB와 Auth, 비공개 Storage를 구성한다. 지정한 Google 계정 하나만 허용한다. 상품 링크를 먼저 영구 저장한 뒤 별도로 구조화 데이터와 Open Graph를 수집한다. 실패해도 링크를 보존하고 선택적 수정을 제공한다.

대표 쇼핑몰을 실제 링크로 확인하고 필요한 처리만 보강한다. 상품 옵션을 보존한 중복 처리와 이미지 사본 저장을 적용한다. iOS 공유 단축어에는 추가 권한만 있는 폐기 가능한 키를 사용한다. 메모, 컬렉션, 구매 상태와 데이터 내보내기 및 복원을 연결한다.

## 가격 확인

지원하는 위시 상품을 하루 한 번 확인한다. 같은 옵션, 통화와 조건의 가격만 비교한다. 실패하면 기존 가격과 확인 시각을 유지하고, 구매완료하면 추적을 중단한다.

GitHub Actions를 한국 시간 06:17, 14:17, 22:17에 실행해 DB 상태, 미완료 수집과 갱신 대상을 확인한다. 인증된 정기 작업, 재시도 제한, 중복 실행 방지와 실패 기록을 적용한다. 무료 한도 안에서 운영한다. 비활동 정지 방지나 예약 실행의 가용성을 보장하지 않는다.

## 실제 연동의 인수 기준

기존 Next.js API·Supabase 구성을 유지한다. 사용자가 요청한 Spring REST Docs, RestAssured와 컨트롤러 BDD 테스트의 목적을 이 스택에 적용한다. API 계약은 요청·응답 테스트로 검증하고 문서와 일치하는지 CI에서 확인한다. 실제 HTTP 요청을 통한 통합 테스트를 둔다. 요청 처리 경계의 단위 테스트는 Given–When–Then으로 정상 입력, 검증 실패, 인증 거부와 오류 응답을 표현한다. 구체적인 도구는 API 연결 단계에서 선택한다.

실제 iPhone 공유 메뉴와 대표 쇼핑몰의 수집 범위를 검증한다. 계정 접근 제한, 단축어 키 폐기, 외부 URL 요청의 사설망 차단, 데이터 내보내기와 복원을 검증한다. 상품 데이터와 인증 정보는 공개 저장소에 포함하지 않는다.

가격 알림, 내부 상품 발견, 공개 공유와 주문 자동 연동은 범위에 없다. 배포 준비와 검증을 마친 뒤 별도 승인을 요청한다.
